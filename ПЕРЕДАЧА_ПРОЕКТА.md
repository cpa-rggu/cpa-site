# Передача проекта: сайт «Африка. Путь к независимости»

Этот файл — полное описание проекта для нового разработчика или ИИ-помощника (ChatGPT, Claude и др.).
Дайте его целиком первым сообщением — дальше помощник сможет работать без предыстории.
Текущее состояние и список дел — в `CHECKLIST.md`, инструкция для владельца — в `ИНСТРУКЦИЯ.md`.

## Что это

Сайт Центра прикладной африканистики РГГУ (ЦПА) о национально-освободительном движении в Африке и роли СССР:
хроника 1957–1994, сюжеты с архивными материалами, передвижные выставки, экспонаты с QR-кодами,
публикации учёных Центра, новости, магистерская программа, страница «О Центре», тестовый личный кабинет.

- Сайт: https://cpa-rggu.github.io/cpa-site/
- Админка: https://cpa-rggu.github.io/cpa-site/admin/
- Репозиторий: https://github.com/cpa-rggu/cpa-site (организация `cpa-rggu`, ветка `main`, публичный)
- Владелец — магистрант, не программист. Объяснять по-русски, просто и по шагам.
- Название проекта — «Африка. Путь к независимости». Название UHURU **не использовать**.

## Как устроено

- **Статический сайт без сборки**: HTML + CSS + обычный JavaScript, без фреймворков и без npm. Внешнее — только шрифты Google Fonts.
- **Хостинг**: GitHub Pages из корня ветки `main`. Выкладка = коммит и push в `main` (владелец делает Push через GitHub Desktop), сайт обновляется за 1–2 минуты.
- **Тексты и данные** лежат в `content/*.json`. Каждое текстовое поле — объект на 5 языках: `{ "ru": "…", "en": "…", "fr": "…", "pt": "…", "sw": "…" }`. Если перевода нет — показывается английский, затем русский (`CPA.tx` в `js/common.js`).
- **Языки**: RU, EN, FR, PT, SW. Выбор запоминается в `localStorage` (`cpa.lang`), можно открыть сразу на языке: `?lang=en`.
- **Админка**: Sveltia CMS 0.250.1 (`admin/index.html`), вход по токену GitHub (classic PAT со scope `repo`). Правки из админки сразу коммитятся в репозиторий.
  - `admin/config.yml` **не править вручную** — он создаётся скриптом `tools/make-cms-config.ps1` (в скрипте описаны все разделы и поля; после правки скрипта запустить его заново).
  - Все языковые подполя необязательные (`required: false`).
- **Общий код**: `js/common.js` → объект `window.CPA`: загрузка JSON (`CPA.start({content, ready, render})`), тексты (`CPA.t('группа.ключ')`, `CPA.tx(obj)`), шапка и меню из 6 пунктов (собирается скриптом по `<body data-page="…">`), выбор языка, кнопка «Войти/Кабинет», свайпы (`CPA.onSwipe`).
- **Стили**: `css/style.css` (общие, главная), `css/pages.css` (внутренние страницы). Телефон — до 760 px.

## Решения владельца (не менять без его согласия)

- Ничего не публиковать и не делать `git push` без явного разрешения владельца.
- Заглушки в `[квадратных скобках]` оставлять как есть — их заполнит Центр.
- «Источники фотографий» в подвале **убраны** по решению владельца — не возвращать (данные сохранены в `content/credits.json`).

- Метки «ПРИМЕР» / «Иллюстрация» на выставках и экспонатах — пока данные не подтверждены.
- Дизайн — по макетам из `design-v2` (в бэкапе: `design-and-sources.zip`). Шрифты: Unbounded, Onest, JetBrains Mono, Oswald. Акцентный цвет `#C8321B`.

## Личный кабинет (Supabase) — тестовый

- Регистрация с подтверждением почты, вход, смена имени и пароля, сброс пароля — через **Supabase Auth** (REST-запросы из `js/account.js`, без библиотек).
- `content/auth.json`: `url` — адрес проекта Supabase, `anonKey` — **публичный** ключ (`sb_publishable_…`). Он и должен лежать на сайте.
- **Секретный ключ (`sb_secret_…` / `service_role`) и пароль базы данных в репозиторий не класть никогда.**
- Пользователи хранятся в Supabase (PostgreSQL), таблица `auth.users`; имя — в `raw_user_meta_data.name`. Своих таблиц пока нет.
- В Supabase → Authentication → URL Configuration: Site URL = `https://cpa-rggu.github.io/cpa-site/account.html`.
- ⚠ Это тест. Для настоящего запуска нужны сервер в России (152-ФЗ о персональных данных) и своя почта для писем.
- Выгрузить пользователей: Supabase → SQL Editor → `select email, raw_user_meta_data->>'name' as name, created_at from auth.users;` → кнопка Export (CSV). Делает владелец — эти данные в бэкап сайта не входят.

## Бэкап и восстановление

- `powershell -ExecutionPolicy Bypass -File tools\backup.ps1` — создаёт `D:\Проект сайта\backups\backup_ДАТА` с полной историей (`site-history.bundle`), файлами сайта, макетами и инструкцией `ВОССТАНОВЛЕНИЕ.txt`.
- Восстановить репозиторий: `git clone site-history.bundle cpa-site`, затем push в новый репозиторий и включить GitHub Pages (подробно — в `ВОССТАНОВЛЕНИЕ.txt`).

## Как начать работу новому помощнику

1. Прочитать этот файл, затем `CHECKLIST.md` (что сделано и что осталось).
2. Перед правками на компьютере владельца — в GitHub Desktop **Fetch origin → Pull**.
3. Делать правки по одной странице, после каждой — объяснить владельцу, как проверить (локально: `tools\serve.ps1`), и отметить в `CHECKLIST.md`.
4. Новые поля в `content/*.json` — добавить и в `tools/make-cms-config.ps1`, затем перезапустить его, чтобы они появились в админке.
5. Коммит и push — только с разрешения владельца.
